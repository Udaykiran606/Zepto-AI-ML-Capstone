2. Global Installation & Dependencies
To set up and run all three modules locally, install the required dependencies:


pip install pandas numpy requests beautifulsoup4 scikit-learn seaborn matplotlib joblib imbalanced-learn chromadb sentence-transformers langgraph fastapi uvicorn pydantic nest_asyncio
🚀 3. How to Execute Each Module
Module 1: Data Pipeline
Extracts raw catalog data from books.toscrape.com, applies median imputation and currency enrichment, stores the normalized schema in SQLite, and cross-validates SQL JOIN queries against Pandas.


python Data_Pipeline.py
Module 2: Analytics & Machine Learning Pipeline
Executes data profiling, defensible cleaning, univariate/bivariate EDA, trains three baseline classifiers, handles class imbalance via SMOTE, performs GridSearchCV hyperparameter tuning, fits a fare regression model, and serializes the final pipeline artifact.


python analytics.py
Module 3: Zepto Support Assistant (RAG & Agent Service)
Initializes local ChromaDB embeddings (all-MiniLM-L6-v2), builds a 3-node LangGraph workflow with keyword-driven intent routing, and launches a FastAPI web service on port 7860.


python main.py
Running via Docker:

docker build -t zepto-support-assistant .
docker run -p 7860:7860 zepto-support-assistant
🏛️ 4. Detailed Module Descriptions & Architecture
Module 1 — Data Pipeline (data_pipeline/)
Purpose: Automated Scraping, Cleaning, Database Normalization, and Query Validation.

Pipeline Flow: Scrape → Clean → Convert → Store → Query → Validate.

Key Components:

Scraper: Navigates paginated categories using BeautifulSoup and requests.

Cleaner: Handles special character encoding (£), strips raw text, converts ratings to integers (1–5), and imputes missing metrics using median values.

Database: Normalizes raw data into 3rd Normal Form (3NF) relational tables (categories and books) with Primary Key / Foreign Key constraints in SQLite (catalog_pipeline.db).

Validator: Verifies SQL JOIN queries against Pandas pd.merge() operations programmatically using .equals().

Module 2 — Analytics & Machine Learning (analysis/)
Purpose: Profiling, EDA, Binary Classification, Hyperparameter Tuning, and Regression.

Pipeline Flow: Ingest → Clean → Univariate/Bivariate EDA → Stratified Split → Classifiers → SMOTE Experiment → GridSearchCV → Regression Side-Task → Serialization.

Key Components:

Cleaning Rules: Drops columns with >30% missingness (deck), applies grouped median imputation for 5%–30% missingness (age), and drops rows for <5% missingness (embarked).

Classifiers Evaluated: Logistic Regression, Decision Tree Classifier, and Random Forest Classifier.

Class Imbalance: Compares Baseline vs Class Weight Balanced vs SMOTE Oversampling (applied strictly to training folds to prevent data leakage).

Hyperparameter Tuning: Fine-tunes Random Forest using 5-Fold Stratified GridSearchCV and evaluates Out-Of-Bag (OOB) score.

Model Serialization: Exports the complete preprocessing and classification pipeline to analytics/fitted_pipeline.joblib.

Key Components:
Ingestion & Embedding Stage (initialize_vector_store):
Reads 8 Zepto policy text documents (doc_01–doc_08) and embeds them using the open-source sentence-transformers model (all-MiniLM-L6-v2) locally into ChromaDB (zepto_policy_corpus).

Intent Classification Stage (classify_intent_node):
Uses a keyword heuristic router (delivery, return, refund, membership, tracking, cancel, gift card, support hours) to classify incoming queries into policy_question or general_question without making external LLM calls.

Retrieval & Answer Generation Stage:

retrieve_and_answer_node: Queries ChromaDB for top-3 matching chunks using cosine similarity. In default mock mode (MOCK_LLM=1), returns a deterministic answer: f"Based on the retrieved context: {top_chunk_snippet}". In real mode (MOCK_LLM=0), formats the prompt using a structured template (Role, Context, Task, Format, Length, Negative Constraint, Few-Shot Example) and invokes the model with retry logic.

direct_answer_node: Handles general non-policy queries by returning a fixed canned string.

Validation Stage (RAGResponseSchema):
Enforces response formatting via Pydantic (answer, sources, confidence).

🎯 5. Design Decisions & Key Assumptions
Module 1: Data Pipeline
Encoding & Politeness: Enforces utf-8 encoding to prevent currency symbol glitches (£) and introduces time.sleep(0.3) delays between requests.

Database Normalization: Decouples categories into a separate table linked via category_id Foreign Key to enforce 3NF standards.

Imputation Strategy: Uses median imputation for missing price/rating values while dropping rows missing critical identifiers (title).

Module 2: Analytics & ML Pipeline
Data Leakage Prevention: Preprocessing transformers (SimpleImputer, StandardScaler, OneHotEncoder) are fitted strictly on training data folds (X_train). SMOTE oversampling is applied exclusively to training data.

Threshold-Based Cleaning: Explicitly drops columns exceeding 30% missingness (deck), imputes columns with 5%–30% missingness (age), and drops rows for columns below 5% missingness (embarked).

Module 3: Zepto Support Assistant
Zero API Dependency: Uses open-source sentence-transformers (all-MiniLM-L6-v2) and local ChromaDB storage, ensuring the system runs 100% offline under the graded baseline (MOCK_LLM=1).

Deterministic Validation: Pydantic output schema validation is enforced across both mock and real execution branches.

Containerization: The Dockerfile packages all dependencies and models, exposing port 7860 for deployment on local Docker engines or Hugging Face Spaces.
